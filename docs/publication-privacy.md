# 公开发布与隐私边界

本公开副本以已提交的 E10 本地工程基线为基础。产品范围、示例源码、迁移、测试、锁文件和需求说明保留；用户的未提交内容及真实云环境配置不在公开范围。

## 发布前检查

- 检查了原仓库全部六个远端分支及可达历史，发现原始验收材料包含本机路径、云环境标识和控制台截图，不能直接公开原仓库。
- 公开副本不继承原仓库的提交历史、Actions 日志、制品或部署记录，也不包含原始 `docs/evidence` 文件。
- 检查公开副本的所有文本，以及两份需求 DOCX 的 ZIP/XML 内容、关系和文档属性；移除了历史命令中的个人绝对路径及 DOCX 作者、最后修改者和时间属性。
- DOCX 的正文、样式、表格和其余排版部件保持原始字节一致；本地原始需求文件保留。
- 检查提交者身份、邮箱、凭据模式、个人目录、联系信息、真实云主机和标识。公开提交只使用项目公开身份及 GitHub noreply 邮箱。
- 没有把真实凭据、数据库、备份、令牌、浏览器配置或用户运行数据复制进公开副本。

检查结果针对实际审阅的发布内容，不构成对未来提交或所有未知泄漏方式的保证。运行时安全评估和云部署验收各有独立范围。

## 验收证据

历史阶段文档保留当时的工程结论和限制；原始日志、截图、报告导出、CI 压缩包与内部运行标识留在私有档案，相关历史链接在公开副本中指向本节。公开版本不通过删除原件或补造材料改变历史结论。

本次发布整理本身不等于重新运行完整工程验收。复核当前源码请按照 README 在隔离本地环境运行真实 PostgreSQL、测试套件及验收器，并将新证据放在被忽略的 `.local` 目录。未经实际执行的项目不能报告通过。

## 贡献要求

只提交合成数据和可复现的代码。不要提交个人路径、私人邮箱、住址、电话、令牌、授权头、数据库连接秘密、真实云环境绑定、账单截图或原始运行材料。`.gitignore` 排除本地配置、数据库、备份、依赖、构建缓存及原始证据；忽略规则不能清除已经进入 Git 历史的内容。

发现隐私或凭据问题时，先停止公开传播和再次推送，保留私下修复所需材料，并按 GitHub 的敏感数据清理流程处理相关历史与缓存。不要在公开 Issue 中粘贴秘密。
